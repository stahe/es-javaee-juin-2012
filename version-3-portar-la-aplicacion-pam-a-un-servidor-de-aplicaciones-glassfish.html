    7. Versión 3: Portar la aplicación PAM a un servidor de aplicaciones GlassFish

    Proponemos colocar los EJB de las capas [business] y [DAO] de la arquitectura OpenEJB/EclipseLink en el contenedor de un servidor de aplicaciones GlassFish.

    La implementación actual con OpenEJB / EclipseLink

    En el ejemplo anterior, la capa [ui] utiliza la interfaz remota de la capa [business].

    Probamos dos contextos de ejecución: local y remoto. En este último modo, la capa [ui] actuaba como cliente de la capa [business], que está implementada mediante EJB. Para operar en modo cliente/servidor, donde el cliente y el servidor se ejecutan en dos JVM separadas, implementaremos las capas [business, DAO, JPA] en el servidor Java EE GlassFish. Este servidor se incluye con NetBeans.

    La implementación que se va a construir con el servidor GlassFish

    • la capa [ui] se ejecutará en un entorno Java SE (Standard Edition)
    • Las capas [lógica de negocio, DAO, JPA] se ejecutarán en un entorno Java EE (Enterprise Edition) en un servidor GlassFish v3
    • El cliente se comunicará con el servidor a través de una red TCP/IP. La comunicación de red es transparente para el desarrollador, aunque este debe tener en cuenta que el cliente y el servidor intercambian objetos serializados para comunicarse, no referencias a objetos. El protocolo de red utilizado para esta comunicación se denomina RMI (Remote Method Invocation), un protocolo que solo se puede utilizar entre dos aplicaciones Java.
    • La implementación de JPA utilizada en el servidor GlassFish será EclipseLink.

    7.1. La parte server- e de la aplicación cliente/servidor PAM

    7.1.1. La arquitectura de la aplicación

    Aquí examinamos el componente del lado del servidor que será alojado por el contenedor EJB3 del servidor GlassFish:

    El objetivo es portar al servidor GlassFish lo que ya se ha desarrollado y probado con el contenedor OpenEJB. Esta es la ventaja de OpenEJB y, en general, de los contenedores EJB integrados: nos permiten probar la aplicación en un entorno de ejecución simplificado. Una vez probada la aplicación, solo queda portarla a un servidor de destino, en este caso el servidor GlassFish.

    7.1.1.4. Configuración del servidor GlassFish

    Todavía tenemos que configurar el servidor GlassFish en dos aspectos:

    • La capa JPA está implementada por EclipseLink. Debemos asegurarnos de que el servidor GlassFish disponga de las bibliotecas necesarias para esta implementación de JPA.
    • La fuente de datos es una base de datos MySQL. Debemos asegurarnos de que el servidor GlassFish disponga del controlador JDBC para este sistema de gestión de bases de datos.

    Es posible que descubras que faltan estas bibliotecas al implementar el módulo EJB. A continuación se muestra una de las varias formas de añadir las bibliotecas que faltan al servidor GlassFish:

    • En [1], consulte las propiedades del servidor GlassFish
    • En [2], anote la carpeta de dominios del servidor. Nos referiremos a ella como <domains>
    • En la carpeta <domains>\domain1\lib, coloque las bibliotecas que faltan. En el ejemplo, se añadieron las bibliotecas de Hibernate (lib/hibernate-tools) y el controlador JDBC de MySQL (lib/misc). Por defecto, el servidor GlassFish incluye las bibliotecas de EclipseLink. Por lo tanto, solo añadiremos el controlador JDBC de MySQL.
    • En [1], en la pestaña [Servicios], iniciamos el servidor GlassFish v3
    • En [2], está activo

    • Línea 14: La etiqueta <jee:jndi-lookup> se utiliza para obtener una referencia de objeto de un servicio JNDI. Aquí, asociamos el bean denominado «metier» con el recurso JNDI asociado al EJB [Metier]. El nombre JNDI utilizado aquí es el nombre portátil (Java EE 6) del EJB.
